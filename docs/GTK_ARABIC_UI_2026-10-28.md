# واجهة GTK 3 العربية — الإصدار 0.1.2-beta.1

## لماذا استبدلنا الواجهة الافتراضية؟

أثبتت اختبارات HP 630 يومي 27 و28/10/2026 أن واجهة Tkinter
كانت تعرض العربية بحروف واتجاه مشوهين حتى مع `justify="right"`.
هذه الخاصية تحاذي النص ولا توفر تشكيل الحروف العربية أو حل Bidi.
بدل إضافة مكتبات لتشكيل السلاسل يدويًا (قد تفسد النسخ والتقرير)،
أصبح التشغيل الافتراضي باستخدام GTK 3 وPango مع
`Gtk.TextDirection.RTL`. تظل صفحة JSON تقنية باتجاه LTR، بينما
يظل التقرير HTML مستقلًا بنص عربي UTF-8.

## ما الذي أُنجز؟

- `inspector/gtk_gui.py`: نافذة RTL جديدة، بطاقة حكم بارزة بالأدلة،
  وست بطاقات هوية/CPU/RAM/تخزين/SMART/بطارية؛ عرض النتائج التقدمية
  دون قرار شراء قبل اكتمال L1، صفحة JSON تقنية منفصلة، وصفحة «حول الفحص».
- `inspector/ui_model.py`: نموذج عرض نقيّ بلا GUI، يقبل تقارير v1
  ويحافظ على حدود الأدلة، ويحول القيم المفقودة إلى «غير متاح».
- `inspector/desktop_backend.py`: يعيد استخدام بروتوكول
  `inspector.core --events` المجرّب وبروتوكول الحفظ
  `pc-inspector-save`، دون إعادة فحص عند فشل الحفظ.
- قائمة حزم Debian Live أضيف إليها `python3-gi` و`gir1.2-gtk-3.0`
  مع الاحتفاظ بخط Tkinter القديم للطوارئ. يبدأ Openbox الآن
  `python3 -m inspector.gtk_gui`.
- صفحة JSON مقروءة بنص أحادي العرض LTR؛ صفحة الملخص عربية RTL
  عبر محرك GTK/Pango. لم يُعدل Schema 1 ولا قواعد SMART ولا وسيط الحفظ.

## اختبارات القبول والقيود

- اختبارات Python لوظائف التقديم تشمل حالات الفحص الجزئي،
  وفشل SMART، وغياب القرص، والقيم غير المتاحة والتواريخ dd/mm/yyyy.
- اختبارات البروتوكول تشمل الفحص مرة واحدة، العودة إلى الصلاحيات
  المحدودة، عدم تكرار الفحص عند timeout، والتحقق من إيصال الحفظ.
- يتضمن CI اختبار إنشاء نافذة GTK 3 فعلية باستخدام `xvfb-run`
  والتأكد من RTL الافتراضي وLTR في JSON ورسالة القرار.
- **لم يُثبت بعد ميدانيًا** على شاشة HP 630 أن التشكيل العربي سليم
  وأن بطاقات المعلومات مريحة عند دقة 1366×768؛ يجب فحص هذه النقاط
  بصور من ISO الجديد. نجحت النسخة السابقة في الحفظ والاسترجاع على
  قسم `PCINSPDATA`، ولم يُغير مسار الحفظ في هذا الإصدار.

## خطة فحص ميداني قصيرة

1. الإقلاع من ISO الجديد عبر مفتاح Ventoy الحالي (بدون أي تهيئة).
2. التحقق من قراءة عناوين العربية وحروفها بشكل طبيعي.
3. متابعة ظهور المواصفات تدريجيًا وعدم ظهور حكم شراء أثناء الفحص.
4. عند اكتمال الفحص: ظهور الحكم «لا يُنصح بالشراء» على قرص Hitachi
   ذي SMART failing، مع السبب الواضح والمعلومات الأساسية.
5. حفظ تقرير جديد على `PCINSPDATA` والتحقق من عدم استبدال
   التقرير السابق (اختبار B على USB حقيقي).
6. الاطلاع على صفحة JSON وتأكيد أن `tool_version` يساوي
   `0.1.2-beta.1`، ثم استرجاع ملفات الجلسة الجديدة بعد إعادة التشغيل.

**قيد مهم:** نتيجة `candidate` هي «مرشح مبدئيًا» وليست شهادة
سلامة أو ضمان شراء. لا توجد خاصية تقييم سعر أو اختبارات L2–L4 بعد.
