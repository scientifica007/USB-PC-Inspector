# تحسين العرض الميداني — تقرير HTML والذاكرة (0.1.4-beta.1)

**التاريخ:** 29/10/2026  
**المرجع:** [PR #3](https://github.com/scientifica007/USB-PC-Inspector/pull/3)  
**آخر إصدار مثبت ميدانيًا عند تنفيذ هذا التطوير:** `0.1.3-beta.1` على HP 630 (Ventoy/Legacy BIOS).

## سبب التعديل

أثبت استرجاع التقرير الواقعي للإصدار 0.1.3 أن ملف `report.json` سليم ومفيد للآلة، لكن `report.html` لم يكن يعرض `purchase_assessment` بوضوح، وكانت تفاصيل SMART الضخمة داخل خلية واحدة تعوق القراءة. كما لاحظنا أن `gtk_gui.py` يتجاهل عنوان RAM الديناميكي في `ui_model.py` ويعرض عنوانًا ثابتًا، في حين أن `MemTotal` للنواة لا يساوي بالضرورة مجموع الذاكرة المركبة فعليًا.

## ما نُفذ في مصدر 0.1.4-beta.1

- **HTML مستقل دون شبكة:** مُلخص قرار الشراء وحجته المباشرة في الأعلى، ثم الأدلة والتحذيرات، وحدود الفحص، وخلاصة المكونات. ملائم لاتجاه RTL والطباعة والشاشات الصغيرة.
- **SMART مفهوم:** يظهر الحكم الفني، رمز `smartctl`، حالة اكتمال القراءة، عدد أخطاء السجل التراكمية، وأسماء سمات SMART التي تحمل `when_failed=now` إن وجدت. تبقى بيانات `diagnostic_evidence` ضمن عنصر `details` قابل للفتح، مع بيان أنها حقول مختارة وليست خرج SMART الخام الكامل. لا تُحوّل الأخطاء التاريخية إلى فشل حالي.
- **تخزين:** عرض GB المقروءة بشريًا مع الاحتفاظ بالحجم الدقيق بالبايت داخل التفاصيل.
- **الذاكرة:** احتساب السعة المركبة من وحدات `dmidecode` (DMI) عندما تكون كل الأحجام قابلة للتفسير (`GB` أو `MB`)، مع عرض توزيع الشرائح إن أمكن؛ وتُعرض `MemTotal` تحت وصف مستقل «الذاكرة التي يراها Linux». عند نقص DMI تظل السعة المركبة **غير متاحة** ولا تُخمن من `MemTotal`. تتبع عناوين بطاقات GTK مفاتيح `ui_model` ولا تبقى ثابتة.
- **الغياب والخصوصية:** لا يستنتج HTML أن غياب بيانات البطارية يعني عدم وجودها أو عطلها. لا تدخل أي سكربتات أو أصول خارجية أو بيانات إضافية عن أقراص USB في التقرير.

## ضمانات التوافق

1. لم يتغير `schema_version=1` أو JSON الخام المولّد بواسطة `inspector.core`، ولا دلالة SMART أو قرار الشراء.
2. لم تتغير `inspector.usb_store` أو `inspector.report_writer` أو بروتوكولات `complete.json` وSHA-256.
3. حقول النص غير الموثوقة (DMI/firmware، أسباب القرار، SMART) تُعرض بعد تهريب HTML.
4. أُضيفت اختبارات Python لقرار الشراء وملخصه وعدم تغيير بيانات المصدر، وتفاصيل SMART وذاكرة مركبة 8GB (2×4GB DDR3) في مقابل `MemTotal` نحو 7.6 GiB، وحالات غياب DMI، واختبارات دخان GTK.

## حدود القبول

**اختبار GitHub Actions للفرع نجح** قبل الدمج، ويشمل `compileall` واختبارات Python وGTK3 بواسطة `xvfb-run` وتدقيق صياغة shell. نجاح الاختبارات لا يثبت جودة العرض بصريًا على كل الشاشات أو أن ISO الجديد فُحص على HP 630. يجب متابعة بناء ISO على `main` ثم تجربة L1 واحدة وحفظ/استرجاع تقرير عند التوفر، دون إعادة بروتوكول اختبار B المزدوج. تبقى اختبارات D وG وUEFI وبلا قرص داخلي معلّقة.

## القرار

نُقلت تحسينات العرض إلى مصدر `0.1.4-beta.1` مع فصلها عن النسخة الميدانية السابقة `0.1.3-beta.1`. لا يوجد مبرر هندسي لإعادة تقسيم USB أو إعادة تنفيذ اختبارات حفظ سبق اجتيازها؛ التحقق التالي محدود بعدم حدوث تراجع في سلوك الحفظ وقراءة تقرير HTML الجديد.
