- [x] شيفرة جرد أولي BIOS/CPU/RAM/بطارية/أقراص/SMART.
- [x] واجهة عربية Tkinter وتقارير JSON وHTML.
- [x] شيفرة حفظ على قسم USB محدد مع منع الكتابة المقصودة على الأقراص الداخلية.
- [x] وصفة بناء Debian Live ISO واختبارات Python آلية.
- [ ] تحقق موثق من نجاح بناء ISO ونتيجة GitHub Actions؛ توجد سيرتا عمل tests.yml وiso.yml، وتشمل مشغلات ISO تغييرات inspector/ وbin/، لكن نتيجة التشغيل لم تُتحقق منها بعد.
- [ ] تحقق موثق من الإقلاع على Legacy BIOS وUEFI.
- [ ] تحقق من الإقلاع على جهاز بلا قرص داخلي.
- [ ] تحقق ميداني من حفظ التقارير على Ventoy أو قسم بيانات مخصص.
- [ ] تدقيق النتائج الفعلية مقابل بيانات SMART الخام في أجهزة متعددة.

**ملاحظة:** وجود الشيفرة/الوصفة لا يساوي إثبات نجاح الإقلاع أو سلامة الأجهزة. لا نعيد كتابة النموذج الحالي دون تقييمه.

## M1 — فحص شراء عام سريع (أولوية P0)

- [ ] فصل collectors وdiagnostic rules وreport models وواجهة المستخدم.
- [x] تفسير smartctl exit bitmask والتمييز بين الإخفاق الحالي وسجلات الأخطاء السابقة، مع حفظ حقول تشخيصية مختارة في JSON واختبارات وحدات مكتوبة. **متبقٍ:** التحقق من تشغيل الاختبارات على CI، وتغطية السجلات التفصيلية والاختبار الذاتي القديم والتحقق الميداني؛ لا يُحفظ كامل JSON الخام مراعاةً للخصوصية.
- [x] بدء الفحص عند فتح الواجهة، وبث جرد BIOS/CPU ثم RAM والبطارية والأقراص وSMART عبر JSONL وعرضه تدريجيًا. **تنفيذ برمجي يحتاج تحققًا ميدانيًا**؛ لا يصدر حكم الشراء إلا مع التقرير النهائي.
- [x] حالات قرار L1 الأربع في الشيفرة والواجهة: مرشح مبدئيًا (بأدلة كافية محدودة)، افحص قبل الدفع، لا يُنصح، غير محسوم. **لم يُثبت تنفيذها الميداني أو نجاح CI بعد**؛ ليست شهادة سلامة أو تقييم سعر.
- [ ] الفصل بين اكتمال الفحص والتقييم الفني؛ عدم استنتاج سلامة من غياب بيانات.
- [ ] UTF-8 وRTL وdd/mm/yyyy في الواجهة: ضبط عرض تاريخ التقرير على dd/mm/yyyy، مع بقاء اختبارات التنسيق البصري على Live USB مطلوبة.
- [ ] قياس زمن L1 بعد الإقلاع على أجهزة متنوعة (هدف أولي 10–30 ثانية، قابل للتعديل). أُضيفت أزمنة المراحل وزمن الفحص من بدء عملية الجمع؛ **لا تشمل زمن إقلاع USB** ولا تثبت الهدف الزمني.

**قبول M1:** إقلاع الجهاز، فحص عام دون ملف إعدادات أو إنترنت، نتيجة موثقة قابلة للحفظ، بلا طرفية وبلا كتابة على الأقراص الداخلية.

## M2 — التقييم التجاري وملفات الشراء الاختيارية (P1)

- [ ] ملف شراء JSON مع schema والتحقق والاستيراد والتصدير.
- [ ] وضع عام افتراضي لا يتطلب أي ملف؛ وضع مخصص عند الطلب فقط.
- [ ] مقارنة مواصفات الإعلان بالواقع؛ شروط إقصائية مقابل تفضيلات.
- [ ] ملفات استخدام قابلة للتخصيص (مكتب، برمجة، تصميم، مونتاج، ألعاب، تعليم...).
- [ ] فصل السلامة التقنية عن ملاءمة الاستخدام والجدوى الاقتصادية.
- [ ] إدخال السعر والضمان وفترة التجربة؛ لا تقييم لسعر السوق دون بيانات حديثة موثوقة.
- [ ] فحص عدة أجهزة بالملف نفسه، مع سجل جلسات ومقارنة قبل الشراء وبعده.

**قبول M2:** نتيجة فحص الجهاز نفسها لا تتغير بتغيير الاستخدام، لكن تقييم الملاءمة يتغير بطريقة مفسرة؛ ويظل الوضع العام صالحًا دون تحضير.

## M3 — قناة محلية لاسلكية وواجهة هاتف عبر المتصفح (P1)

- [ ] خدمة API محلية مع حدود صلاحيات وتوثيق عقد v1.
- [ ] بث التقدم والأحداث دون نقل صورة الشاشة.
- [ ] دعم شبكة مشتركة/Hotspot الهاتف أولًا، وAP من الحاسوب إن كان مدعومًا.
- [ ] اقتران QR مع رمز مؤقت، تأكيد متبادل، وتشفير ومصادقة محليين.
- [ ] تنزيل التقارير، رفع ملفات المتطلبات، إدخال السعر والملاحظات.
- [ ] معالجة انقطاع الاتصال وإعادة الاقتران؛ عدم توقف الفحص.
- [ ] اختبارات أمنية: هاتف غير مقترن، إعادة استخدام رمز منتهي، تجاوز الصلاحيات، رفع ملف غير صالح.

**قبول M3:** فحص USB مستقل، عرض النتائج من الهاتف لاسلكيًا ونقل تقرير مطابق دون إنترنت أو أوامر طرفية؛ لا اتصال هاتف لا يعني فشل الفحص.

## M4 — Inspector Mobile لتطبيق Android (P1)

- [ ] تطبيق Android مستقل مع دعم نسخة Android المستهدفة بعد التحقق من الأجهزة المتاحة.
- [ ] اقتران وإعادة اتصال، لوحة تقدم مباشرة، حفظ تقارير محليًا.
- [ ] ملفات شراء اختيارية، مقارنة أجهزة، مشاركة التقارير، تحكم بفحوص مسموحة.
- [ ] التحقق من التوافق مع هاتف محدود الموارد، والعمل دون إنترنت.
- [ ] إبقاء واجهة المتصفح المحلية بديلًا متاحًا.

**قبول M4:** اتصال آمن، نقل ثنائي الاتجاه، تحكم بالتطبيق، وسجل تقارير على الهاتف.

## M5 — فحوص معمقة وقرار الاحتفاظ/الإرجاع (P2)

- [ ] L2: SMART تفصيلي، بطارية، حرارة، شاشة، لوحة مفاتيح، منافذ وشبكة.
- [ ] L3: RAM/قراءة تخزين غير مدمرة/استقرار وحرارة؛ بموافقة صريحة.
- [ ] L4: اختبارات استقصائية طويلة وتحليل أخطاء متقطعة.
- [ ] إدارة تقدم وإلغاء وحدود وقت وحرارة، ومنع الكتابة على الأقراص الداخلية افتراضيًا.
- [ ] مقارنة جلسة الشراء بجلسة ما بعد الشراء، وتقرير احتفظ/أرجع/افحص أكثر.

**قبول M5:** كل اختبار له حالة تنفيذ منفصلة عن الحكم، وأدلته وحدوده، ويمكن إيقافه بأمان حيث ينطبق.

## M6 — AI Agent اختياري (P2)

- [ ] تعريف أدوات قراءة/فحص مسموحة، ومنع shell العام.
- [ ] وكيل يفسر النتائج ويقترح الاختبار التالي بناءً على الوقت والمخاطر.
- [ ] توصيات ملاءمة وشراء وإرجاع مدعومة بالأدلة لا بأرقام مختلقة.
- [ ] موافقة واضحة قبل إرسال بيانات إلى خدمة سحابية، مع إخفاء المعرفات الحساسة افتراضيًا.
- [ ] فحص إمكانات النماذج المحلية لاحقًا، دون جعلها شرط تشغيل.

**قبول M6:** الفحص الأساسي يعمل بلا AI؛ لا يطلق الوكيل اختبارًا حساسًا دون موافقة ولا يدعي قياسات غير موجودة.

## M7 — التحكم الكامل بسطح المكتب (P3)

- [ ] تقييم VNC مؤمن أو بديل مناسب لجلسة Live.
- [ ] مشاهدة الشاشة، فأرة، لوحة مفاتيح؛ تفعيل صريح وإغلاق تلقائي.
- [ ] اختبار الأداء على عتاد ضعيف والتشفير والصلاحيات.

**قبول M7:** لا توجد جلسة تحكم كاملة افتراضية، ولا يتم تجاوز موافقة مالك الجهاز.

## M8 — التحقق قبل الإصدار المستقر

- [ ] اختبارات على HDD وSSD وNVMe، حواسيب محمولة ومكتبية.
- [ ] اختبار Legacy/UEFI، وجود/غياب أقراص، Wi-Fi متاح/غير متاح، وانقطاع الشبكة.
- [ ] اختبار حفظ USB على Ventoy ومفتاح مخصص؛ عدم الكتابة على أقراص الهدف.
- [ ] اختبارات تجريبية في محل بيع بموافقة البائع؛ قياس الزمن وعدد النقرات ووضوح القرار.
- [ ] توثيق نسب التغطية والأخطاء والقيود؛ مراجعة شروط توزيع الأطراف الثالثة والترخيص.

## ثوابت السلامة

1. لا كتابة على الأقراص الداخلية أو تغيير firmware.
2. لا تُعامل البيانات الناقصة على أنها سلامة أو عطل مؤكد.
3. لا اختبارات ضغط/فحوص طويلة أو كتابة افتراضيًا.
4. ساعات تشغيل القرص ليست إثباتًا لعمر الجهاز أو كونه جديدًا.
5. لا يُشترط تحضير منزلي، هاتف، إنترنت، أو AI.
6. لا يمتلك الهاتف أو الوكيل وصولًا عامًا إلى shell أو root.
7. لا يُدّعى نجاح نقل تقرير أو حفظه دون تحقق.
